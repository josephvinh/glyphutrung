> **Ngày:** 2026-09-22 · **Nhánh:** `claude/web-optimization-plan-yj9wsu`
> **Phạm vi:** hiệu năng tải trang (front-end) + phục vụ tệp tĩnh. Không đụng nghiệp vụ.
> **Nguyên tắc:** làm **từng Task, app luôn chạy được** sau mỗi Task; ưu tiên việc

---

## 0. Hiện trạng — những gì ĐÃ tốt (không cần đụng)

Đây là một app PHP thuần đã được tối ưu khá kỹ. Ghi lại để **không làm lại**:

| Hạng mục | Trạng thái |
|---|---|
| Gộp CSS/JS | ✅ `bundle.php` gộp ~30 request còn 2 (CSS + JS) cho production |
| Font | ✅ Tự host, subset theo `unicode-range`, `font-display: swap` |
| Icon | ✅ Lucide rút gọn còn 76 icon (16 KB thay vì 410 KB) |
| Render | ✅ Lazy-mount từng màn bằng `<template x-if>` (không render sẵn 21 màn) |
| Thư viện QR | ✅ `jsQR` (128 KB) + `qrcode` (24 KB) **đã** nạp động chỉ khi mở màn |
| Service Worker | ✅ Cache-first + stale-while-revalidate cho tĩnh; API luôn đi mạng |
| Cache tĩnh | ✅ `.htaccess` đặt `max-age=1 năm, immutable` + cache-bust `?v=<mtime>` |
| **API JSON** | ✅ **Đã nén** gzip/brotli trong `api/_bootstrap.php` + scope payload theo vai |
| CSDL | ✅ Index đủ trên bảng nóng (`attendance`, `enrollments`, `assignments`); PDO singleton, prepared statements |
| Payload boot | ✅ Đã scope theo phạm vi (Admin 4.8MB→141KB) — xem plan `2026-09-07-toi-uu-tai-toan-doan.md` |

**Kết luận:** phần nghẽn "to" đã xử lý. Kế hoạch này nhắm vào các **khe hở tĩnh còn sót**.

## 2. Kế hoạch — theo thứ tự ưu tiên

### Task 1 — Nén bundle tĩnh (P1) 🎯 *ưu tiên cao nhất, rủi ro thấp nhất*

**Mục tiêu:** `bundle.php` (JS + CSS) và trang HTML được nén như API.

**Cách A (khuyến nghị) — nén ngay trong PHP, không phụ thuộc cấu hình hosting:**
- Trong `public/assets/js/bundle.php` và `public/assets/css/bundle.php`: thêm khối
  bật `ob_gzhandler` (kèm brotli nếu có `brotli_compress`) **giống hệt** đoạn đã có
  trong `api/_bootstrap.php` — tái dùng, đừng viết mới. Kiểm `HTTP_ACCEPT_ENCODING`
  và `zlib.output_compression` trước khi bật (idempotent, an toàn).
- Trong `public/index.php`: trang production đã `ob_start()` để xoá comment — chỉ cần
  đổi thành `ob_start('ob_gzhandler')` (hoặc bọc thêm) khi client nhận gzip.

**Cách B (bổ sung, không thay thế) — `.htaccess`:** thêm khối `<IfModule mod_deflate.c>`
nén `text/html`, `application/javascript`, `text/css`. Bọc `<IfModule>` theo đúng
phong cách file (hosting dùng chung có thể thiếu module). Vì bundle là `.php`, phải
nén theo `Content-Type` chứ không theo đuôi tệp.

> Làm **Cách A** trước (chắc ăn, không phụ thuộc Apache). Cách B là lớp thêm.

**Kỳ vọng:** JS 287 KB → **~75 KB**, CSS 52 KB → **~10 KB** trên đường truyền (lần mở đầu).
**Rủi ro:** rất thấp — chỉ đổi tầng vận chuyển, nội dung y nguyên; SW cache lại bản đã nén bình thường.
**Kiểm chứng:** `curl -H "Accept-Encoding: gzip" -I <url>/assets/js/bundle.php` phải thấy `Content-Encoding: gzip`.

---

### Task 2 — Build & commit `bundle.min.js` (P2)

**Mục tiêu:** production phục vụ JS **đã minify**, không còn nối thô.

- Chạy `npm run build` (đã có `build/minify.cjs` + `esbuild` trong devDeps) để sinh
  `public/assets/js/bundle.min.js` (song song `bundle.min.css` đã có).
- `bundle.php` **đã** có sẵn logic: nếu `bundle.min.js` mới hơn mọi tệp nguồn thì
  `readfile` nó, ngược lại nối thô. → Chỉ cần build ra file là tự có hiệu lực.
- Commit file `.min.js` (repo đã theo quy ước commit `bundle.min.css`).
- **Quy trình:** ghi rõ trong `docs/` rằng sau khi sửa JS module phải chạy
  `npm run build` trước khi deploy — hoặc thêm bước vào `.cpanel.yml` (xem Task 6).

**Kỳ vọng:** 287 KB → **~150 KB** trước gzip; cộng Task 1 → **~70 KB** trên dây.
**Rủi ro:** thấp — có fallback nối thô nếu min cũ hơn nguồn (không bao giờ phục vụ mã hỏng). Cần smoke-test app sau minify.

---

### Task 3 — Dọn ảnh mồ côi + hoàn thiện PWA icon (P3)

- Xác nhận `logo.png`, `icon-512.png`, `optimized/*` không dùng (đã grep, không thấy).
  - Nếu login/branding cần logo: nối vào bằng `<picture>` (avif→webp→png) — bản
    `optimized/` đã sinh sẵn, chỉ chưa nối.
  - Nếu không dùng: chuyển khỏi web root (hoặc xoá) để nhẹ bản deploy.
- Bổ sung `icon-192` và `icon-512` vào `manifest.json` (hiện chỉ có svg + 180) để
  Android hiển thị icon PWA sắc nét và đủ điều kiện "cài như app".

**Kỳ vọng:** deploy nhẹ ~500 KB; PWA icon chuẩn. **Rủi ro:** thấp (kiểm login còn logo trước khi xoá).

---

### Task 4 — Rà soát font (P4) *tuỳ chọn, làm sau*

- Kiểm thực tế các weight **đang dùng**: theo comment repo, `900` dùng 151 chỗ, `800`
  không dùng. Rà `grep` `font-black/bold/semibold/medium` để bỏ weight thừa.
- Cân nhắc **một họ chữ** cho thân bài nếu Inter và Be Vietnam Pro trùng vai trò —
  mỗi họ bỏ đi tiết kiệm ~5 tệp × 2 subset.
- Cân nhắc `<link rel="preload">` cho **đúng 1-2 tệp font** dùng ngay ở màn đầu
  (weight 400/600 vietnamese) để bớt nhấp nháy chữ.

**Kỳ vọng:** giảm vài trăm KB font ở các phiên chưa cache. **Rủi ro:** trung bình — phải soát kỹ kẻo mất weight đang dùng.

---

### Task 5 — Kiểm chứng số đo (bắt buộc, xuyên suốt)

- Trước/sau mỗi task: đo bằng DevTools → Network (throttle "Slow 4G"), ghi lại
  **kích thước truyền** và **thời gian tới lúc app tương tác được**.
- Lighthouse (mobile) cho `index.php` sau đăng nhập: ghi điểm Performance + LCP/TBT.
- Bảng "trước/sau" bổ sung vào cuối tài liệu này khi thực thi.

---

### Task 6 — (Tuỳ chọn) tự động hoá build khi deploy

- Thêm bước `npm ci && npm run optimize` vào `.cpanel.yml` để `bundle.min.*` và ảnh
  luôn được sinh lúc deploy, tránh quên chạy tay (nguyên nhân P2).
- Chỉ làm nếu môi trường cPanel có Node; nếu không, giữ quy trình thủ công + ghi chú rõ.
